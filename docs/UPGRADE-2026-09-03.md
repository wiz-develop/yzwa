## Production release

1. Create fresh production file and database backups and record hashes.
2. Put the site in maintenance mode and preserve `wp-config.php`, uploads, mail settings, server `.htaccess`, the static `recruit` site, and the XServer TypeSquare plugin.
3. Deploy WordPress core and each plugin separately, checking the public site and log after each update.
4. Deploy the maintained CFS build and the scoped `base` theme fixes from `test`.
5. Do not deploy staging `.htaccess`, staging URL rewrites, staging database values, or staging recruitment URLs to production.
6. Run the WordPress database upgrade, clear caches, and verify the hidden login URL, Site Health, REST, loopback, Cron, sitemap, and public pages.
7. Run contact form delivery tests only with explicit approval because production recipients may receive them.
8. Confirm an empty production error log before ending maintenance mode.

## Rollback

1. Restore the fresh production file backup, excluding only files explicitly documented as runtime cache.
2. Restore the matching database dump.
3. Restore the original server `.htaccess` and `wp-config.php` if either changed.
4. Clear PHP, WordPress, and CDN caches.
5. Verify the home page, hidden login, REST, Cron, recruitment site, and form display before reopening the site.
